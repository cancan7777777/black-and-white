# LabVIEW 接入本机 Egaroucid 对弈

- 用户明确授权在上一版复查后接入本机已下载的 Egaroucid。沿用 [#16](https://github.com/cancan7777777/black-and-white/issues/16) 和 [#17](https://github.com/cancan7777777/black-and-white/issues/17)。分支 `task/17-egaroucid-labview` 基于界面与爱心动画提交 `d3e7427`。
- 软件基线已复查。原版上位机 77 项检查通过，原生闯关、按键路径和 LED 动画测试通过，爱心版 HEX 的 SHA-256 与上一轮记录一致，PR #27 同步至对应提交。实体板上的灯效与串口联调仍待实际验收。本次先验收可以独立运行的离线对弈，不进行烧录。
- 对照[官方控制台说明](https://www.egaroucid.nyanyan.dev/en/console/)和[官方 7.8.2 发布页](https://github.com/Nyanyan/Egaroucid/releases/tag/console_v7.8.2)，运行本机 Windows x64 AMD AVX512 版本的 `-help` 和一次白棋实算。控制台用 `setboard` 读取 64 格及执棋方，`go` 在安静模式下向标准输出写出坐标，提示符走标准错误。实测 D3 后推荐 C3，进程退出码 0，启动到退出约 543 ms。保留资源目录原位，通过本地进程调用，仓库只提交桥接代码，不上传 GPL-3.0 引擎或资源。
- 接入方案是单独加入 Egaroucid 对弈，玩家执黑，外部 AI 执白，底层使用普通模式。依据已确认的棋盘运行搜索，并在搜索后再次核对棋盘、回合和版本，通过原有落子协议提交；沿用原先一方无合法落子就终局。超时或失败恢复手动。计划用本机真实引擎验证完整离线对局、暂停／断开时不提交过期落子，并复跑原有模式。

## 实施记录

- 首次 x86 .NET Framework 端到端回归发现，重定向标准输入时进程在第一条命令前收到 UTF-8 BOM。命令行直测使用不同运行时，所以只在与 LabVIEW 同类的运行时上复现。先发送空行承接 BOM，只忽略对应的前导错误，并严格检查其后的唯一坐标和翻子合法性。
- 在现有 C# 组件内直接管理控制台进程。搜索后台运行，两个线程，默认等级 5。超时上限为 10 秒。对局切换、暂停或断开连接时取消过期搜索。提交白棋请求时沿用原先的版本字段，由仿真或 STM32 确认生效。
- 使用 `tools/build-labview.ps1 -OutputDirectory build/labview/egaroucid/bin -EgaroucidExecutable <本地控制台程序>` 完成构建和回归。真实 7.8.2 与黑方离线走完 52 手，终局黑 23、白 33，并通过引擎路径缺失、暂停期间无落子、继续、下一局、断开重连及旧结果隔离检查。当次共通过 402 项上位机断言，原生四关规则和点阵动画检查通过。
- 已安装新版 x86 组件及本地引擎路径，复制后核对哈希。ActiveX 启动检查检测到已有 LabVIEW 会话，保留当前会话和现有 `Main.vi`。本次端到端对局使用相同的 .NET 前面板组件与固件仿真，重新启动 LabVIEW 后可在 VI 中载入新版。实体键盘对 AI、串口和点阵动画待上板验收。
