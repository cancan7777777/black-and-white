# S16 闯关人机对弈

- 用户指出进阶版闯关仍需双方手动落子，并确认「把闯关改成人机对弈」。沿用 [#11](https://github.com/cancan7777777/black-and-white/issues/11)，关联 [#17](https://github.com/cancan7777777/black-and-white/issues/17)，进阶主实现位于 PR #25。分支 `task/11-challenge-computer` 从 `task/11-advanced-modes` 建立。
- 任务书 A02 规定恰好 188 分和两连败。原总体方案把人机与闯关分别列出。本轮以用户新决定为准，让 S16 的闯关由玩家执黑，STM32 执白。普通与计时仍由双方手动落子。保留 188、两连败、退出和终局规则。
- STM32 执行轻量、可复现的白方选点。真实局和离线模拟编译同一 C 代码。LabVIEW 协商人机能力、提示电脑回合并同步每手确认棋盘。核查暂停恢复、手动白方请求、复盘与分数边界，重新构建最新 HEX。实板操作待用户现场验收。

## 同日 · 自动应手与实体点阵配色

- 白方轮到电脑时等待 250 ms 后自动落子，暂停和编辑冻结等待。使用棋规已有合法性检查，优先下角，否则选择翻棋最多的格子。串口新增 `SYNC2/GAME2` 协商能力，保留两代旧串口帧兼容。电脑在实体和离线模拟中走同一状态机。
- 首次 C 测试时，先前的强制电脑落子用例已启动计时基准，导致后续回绕测试继承了时钟。将回绕用例还原为全新会话后通过。应用层用例验证 S16 后 S6 的黑棋帧、拒绝人工白棋、暂停等待以及恢复后 STM32 主动发布电脑落子。合法对局累计 `45 + 45 + 36 + 31 + 31` 恰好达到 188 分。
- x86 上位机通过 70 项检查，包括面板切入闯关、禁用电脑回合的落子按钮、收到自动应手及每模式档案。当前 LabVIEW 进程占用旧模拟 DLL，因此本地新组件使用 `OthelloSimulatorV2.dll`，对应程序集和模拟库已成对更新。
- 接续用户对实体蓝白辨识度的反馈，改为黑方橙色、白方青色和空格紫色光标。有子的光标按同一色相提亮。调度方式、强度上限与 WS2812 的 GRB 发送顺序沿用现有设置，效果待实体点阵复验。
- 当前 Keil 从同一源码构建，人机与配色合并后 0 错误、0 警告。ATK-XISP 用文件为本地 `build/Othello_Challenge_AI.hex`，45,043 字节，1,003 条 Intel HEX 记录全部校验，SHA-256 前八位 `609FA6F8`。主安装路径下的 `BasicTests.exe` 再次通过 70 项。
- 本轮保留正在使用的 LabVIEW 会话与工作区中已有的 `Main.vi` 修改。重新打开 VI 后可载入新版组件。板卡需要烧录新版 HEX 才能使用人机闯关与配色，本轮未执行实板写入。

## 同日 · 四关计分规则

- 用户确认沿用玩家执黑、STM32 执白的人机闯关，并指定四关系数 `0.5 / 1 / 1.5 / 2`。每关结算以黑棋余数乘系数，累计达到或超过 188 分时 `WIN`。这是对先前「恰好 188」的明确更改。范围包含下位机、离线模拟、LabVIEW 计分与档案、自动测试和新版 HEX。
- 沿用连续两败时 `OVER` 的规则。四关用尽而总分低于目标也 `OVER`。通过结算后进入下一关，编辑或中途重开不加分，同一关只可结算一次。所用计分单位精确到 0.5 分。基于 `7c7b7ea` 在已有 #11 分支和 PR #26 推进。
- STM32 在关卡结束时累计，`SYNC3/GAME3` 同步关卡、本关半分单位和累计的半分余数。LabVIEW 显示关卡与系数，并以十进制保存成绩、导出 CSV。旧固件仍可回退连接，旧 XML 整数成绩可读。
- 原生测试覆盖 187.5 未赢、188 和 188.5 获胜、各关系数、四关上限、两连败与重开。使用规则合法的人机对局得到 `20 + 40 + 60 + 80 = 200` 并触发 `WIN`。LabVIEW 75 项自动检查通过。Keil 0 错误、0 警告。新 HEX 本地交付路径为 `build/Othello_Challenge_4Stages.hex`，实板烧录和 LED 展示待现场验证。
