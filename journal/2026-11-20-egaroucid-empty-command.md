# Egaroucid 空命令报错修复

- 用户确认选择正确程序后仍显示 `[ERROR] command `` not found`。本轮核对实际本机配置、复现 LabVIEW 运行时的标准输入编码并修正引擎命令启动顺序。沿用 AI [#17](https://github.com/cancan7777777/black-and-white/issues/17)，起点 `70b2fda`。
- 本地 `EgaroucidPath.txt` 指向已存在的 Egaroucid Console 7.8.2 AMD AVX512。本次优先对照无控制台进程和 UTF-8 控制台，再复跑整个棋局及模式验收。

## 复现、修复与验证

- 在 x86 无控制台程序中复现。实际重定向标准输入为 936 代码页，预导字节数为 0。旧逻辑仍发送一行空白。EN 退出码为 0，先返回截图中的空命令错误，随后返回合法 `c3`。上位机按错误处理，白棋保持未落。
- 仅在 .NET 输入编码有预导字节时预留第一行，只识别预留行的已知响应。无预导时直接发 `setboard`。后续错误、坐标和翻子合法性继续校验。
- 无控制台图形进程的端到端复测通过。D3 后 EN 下 C3，固件仿真确认黑白各 3 枚、回到黑方。新增真实引擎的 CP936 和 UTF-8 带预导用例。共 447 项上位机检查通过，含 52 手离线引擎对局和实体 S15 路径模拟。
- 已部署并核对新版 `Othello.Basic.dll` 和测试程序。现有引擎配置及 V3 模拟库经校验可继续使用。当前 LabVIEW 会话保留，需完全退出并重开 `Main.vi` 才加载修复后的组件。
