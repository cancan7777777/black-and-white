# LabVIEW 路线可行性、硬件对应机制与课时化制作方案

版本：v0.1 草案（2026-11-17，Asia/Shanghai）。状态：**待用户确认**，确认前不安装环境、不接线、不写 VI 与固件。对应任务 T18。

本文回答三个问题：LabVIEW 能不能按任务书要求做完；怎么保证"跟硬件对应"；按课时怎么切。

## 1. 结论

1. **能，但只覆盖上位机那一半。** 上位机侧要求（B06、B07、A05、A06、A07，以及 C01 的界面部分和 C03 的联调）LabVIEW 可以做，而且这就是 `黑白棋课程设计总体方案.md` 已经选定的路线（LabVIEW 9 作唯一主界面）。
2. **不能只用 LabVIEW 完成整个任务书。** B01–B05、A01–A04 的执行端必须在 STM32：键盘扫描、点阵驱动、合法落子与翻子、终局判定、模式状态、计时、闯关累计、作弊编辑。LabVIEW 也**无法**直接产生 8×8 WS2812B 需要的 ~800 kHz 单线归零码时序——没有 STM32 参与，就没有"点阵"可谈。
3. **"跟硬件对应"不取决于界面画得好不好，取决于三件事**：板端先有最小闭环固件；一张单一真源映射表被三处同时引用；逐格逐键的真机验证留证。这三件事没做，界面再像也不算对应。

一句话：LabVIEW 负责"看得见、点得动、存得下"，STM32 负责"真的亮、真的判、真的算"，两边只通过冻结的串口帧对话。

| 要求 | 执行端 | LabVIEW 的角色 | 硬件对应证据 |

| A06 历史回看 | LabVIEW | 主实现 | 保存文件 + 逐步回看截图 |

## 3. 硬件对应机制（最关键的一节）

### 3.1 单一真源映射表

一张表，四种映射，三处引用（`docs/hardware-map.md` ↔ 固件 `hw_map.h` ↔ LabVIEW 常量），任何一处改动必须同步另两处，并由脚本比对差异。

| 映射 | 必填字段 | 为什么必须有 |
|---|---|---|
| 引脚 | MCU 引脚 / 器件信号 / 方向 / 复用功能 / 实际板卡 / 资料来源 | 换板或换定时器通道就会变，原稿引脚只是候选 |
| 点阵 | 逻辑 (行,列) / 灯珠索引 / 蛇形或行优先 / 颜色字节序（GRB）/ 空-黑-白三色值 | 蛇形方向错一格，整块棋盘镜像；颜色序错，黑白互换 |
| 键盘 | 键帽 / 行列 (X,Y) / 主功能 / 复用功能 | 16 键要覆盖 64 格 + 六类控制，必须靠复用 |
| 协议 | 帧类型 / 方向 / 字段 / 板端变量 / VI 控件 / 幂等键 | 帧和界面控件对不上，就会出现"点了没反应" |

### 3.2 板端最小闭环（必须先于 LabVIEW）

LabVIEW 之前，板子要能对两条原型命令应答：

- 单灯：`@SET,<seq>,<idx>,<rrggbb>,<crc>\n` —— 点亮第 idx 颗灯，用于逐格对位。
- 快照：`@SNAP,<seq>,<64 字节状态>,<crc>\n` —— 一次性吐出全盘，用于双端比对。

只要这两条能工作，"我点哪、实物亮哪"就被证明了；后面所有界面都建在这两条之上。

### 3.3 逐格/逐键验证留证

| 验证项 | 通过判据 | 留证形式 |
|---|---|---|
| 64 格点灯 | 64/64 格与逻辑坐标一致 | 逐格照片或录像 + 表格打勾 |
| 16 键键值 | 16/16 键上报的行列与键位表一致 | 串口键值日志 + 键位表 |
| 双端一致 | 同一时刻两端的 64 字节状态完全相同 | 快照字符串对照记录 |
| 非法输入 | 占用格、不翻子、越界、暂停中落子：棋盘不变 | 用例表 + 前后快照 |
| 断线重连 | 重连后按最新快照恢复，不重放旧落子 | 拔插录像 + 日志 |

量化目标：确认落子后双端更新 ≤ 200 ms（项目自定目标，任务书未规定毫秒阈值）。

## 4. LabVIEW 9 的现实约束与对策

LabVIEW 9（2009 年版）年代较早，以下是会影响"能不能跟硬件对上"的具体点，不是风格建议。

| 约束 | 会怎么坏 | 对策 |
|---|---|---|
| `Bytes at Port` 轮询 | 读到半包或空读，界面卡住 | 帧以 `\n` 结尾，VISA 配置终止符读取 |
| UI 事件里等串口 | 前面板假死，像"程序崩了" | 通信放独立循环，事件结构与队列传数据 |
| 无内置 CRC16 / JSON | 校验和解析要自己写 | 纯 ASCII 定界文本 + 手写 CRC16 查表 |
| 串口按字节收发 | 中文混进帧里就乱码 | 协议全 ASCII；中文只出现在界面文字 |
| 64 个布尔控件画棋盘 | 刷新慢、闪烁、和实物不同步 | 单个 Picture 控件整幅重绘（U8 数组 → 颜色映射） |
| 32/64 位与 NI-VISA 版本 | 端口打不开或运行时崩 | K0 用最小回环实测；不通过就换版本（需你确认） |
| 文件持久化 | 重开读不回来 | TDMS 或 CSV，时间戳统一格式 |

## 5. 课时化制作计划（草案）

设计原则：

1. **每课时收尾必须是一个能演示的双端闭环**，不是"画完一个面板"。
2. **每课时出口 = 证据 + 一次提交**，证据指照片、日志或快照对照，写进 journal。
3. **禁止"先把界面做完再对硬件"**——那样一定对不上；第 K5 课时就要让 PC 点亮真实的一格。

| 课时 | 主题 | 硬件对应（真机必须可见） | LabVIEW 产出 | 覆盖 | 出口条件 |
|---|---|---|---|---|---|
| K0 | 环境门槛与对应基线 | 板子能下载、USB-UART 回环通、点阵首格点亮 | 串口最小收发 VI（开/关端口、发一行、收一行） | B07、C03 前置 | 回环截图 + 硬件清单 |
| K1 | 点阵映射 | 逻辑 (r,c) → 灯珠索引 → 实物位置，逐格点亮 | 只读监视（或暂不做） | B01 显示 | 64/64 格对应表 + 照片 |
| K2 | 键盘映射 | 16 键真实行列与键位表一致 | 无 | B01 输入、A01 前置 | 16/16 键值日志 |
| K3 | 规则内核 | 开局、必翻子、非法拒绝、终局 | 无（脚本驱动对局） | B02、B03、B04 | 规则用例表通过 |
| K4 | 串口端点 | HELLO / SNAP / ACK / ERROR + CRC，拔插重连 | 无（脚本核帧） | B05 | 帧日志 + 重连快照 |
| K5 | **首次与硬件对应** | PC 点"点亮 (r,c)"→ 实物该格亮 → 板端回读确认 | 串口配置页 + 单格点灯/回读面板 | B07、B06 起点 | 视频：点击与实物同屏 |
| K6 | 棋盘同步 | 实体键盘落子 → 实物与虚拟棋盘同帧一致 | 8×8 Picture 棋盘 + SNAP 解析 | B05、B06 | 双端一致记录（≥10 次） |
| K7 | 上位机落子 | UI 点击 → STM32 裁决 → 双端同步；非法请求棋盘不变 | 落子请求 + 等确认 + 错误提示 | B06 | 合法/非法各 5 例 |
| K8 | 控制与异常 | 开始/暂停/继续/重开/结束/模式；断线恢复 | 控制按钮组 + 重连逻辑 | A01、C03 | 状态转换表两端各一遍 |
| K9 | 闯关与计时 | 188 → WIN、连输 2 局 → OVER、计时结算 | 模式设置 + 本局分/总分/连败/计时显示 | A02、A03、A05 | 边界用例（187/188/超 188、输输、输平输） |
| K10 | 作弊编辑 | 进编辑态后点阵可改，双端同步，不误走合法落子 | 编辑面板 | A04、A05 | 编辑前后双端快照 |
| K11 | 历史保存与回放 | 从板端快照重建整局 | 保存、选择、逐步回看 | A06 | 回放录像 + 文件 |
| K12 | 排行榜与导出 | 数据来自真实对局 | 分模式排行、时间/得分、导出 | A07 | 每模式 ≥5 条 + 重开可读 |
| K13 | 验收与演示 | 全部硬件证据汇总，连续 10 局 / 30 min | 界面整理、量纲标注 | C01、C02、C03 | 验收矩阵逐项填状态 |

课时数、每次课时长度、是否含报告撰写，全部**待你确认**；上表按 14 段切，可按实际课时合并（K1+K2、K11+K12 最容易被合）。

## 7. 怎么证明"跟硬件对应"

验收时只看这五项，不看界面截图是否漂亮：

1. 64/64 格点灯对应表全绿，附照片。
2. 16/16 键值对应全绿，附日志。
3. 连续对局中双端 64 字节状态逐字节一致。
4. 四类非法输入全部不改变棋盘。
5. 断开上位机后，下位机仍能独立完成一局（若老师要求独立运行，见 D07）。

以上全部需要真机证据；在拿到证据之前，本文与相关 Issue 一律标记为未执行。
